# ReachTrail 版 3 向け監査（2026-09-09）

14 日間・12 名以上のクローズドテストを前提に、テスターが日常利用で踏む不具合と UX の摩擦を洗い出した。
`lib/app.dart`（約 4,700 行）の分割はテスト前提ではないため対象外。すべて局所修正で入る。

## 重大（テストが成立しなくなるもの）

| ID | 内容 | 場所 | 修正 |
|---|---|---|---|
| C-1 | 通信不可でコールドスタートすると `/auth/google` 失敗→サインイン画面から進めず、端末内の記録も見られない | `google_auth_service.dart` `attemptLightweightAuthentication` / `app.dart` 起動処理 | セッションとユーザー最小情報を prefs にキャッシュし、先にホームを表示。裏で再認証し、失敗時は検索だけ無効化するバナー |
| C-2 | `ReachTrailController.load()` の永続化読み込みが try の外で、例外時は `isBootstrapping` が true のまま無限スピナー | `app.dart` `load()` | try/catch/finally。失敗時はエラー＋再試行（未使用の `reloadConfig()` を活用） |
| C-3 | 保存キーがユーザー非依存で、別アカウントでサインインすると前のユーザーの記録が見える | `persistence_service.dart` | `lastUserId` を保存し、別 ID でのサインイン時に `clearAll()` |

## 重要（報告ノイズ・離脱の主因）

| ID | 内容 | 修正 |
|---|---|---|
| I-1 | 基準地点未設定で検索すると `dist` だけ付いた不正クエリ→400→無関係な文言 | `dist` を `baseLocation != null` 条件下に。未設定時は検索ボタン無効＋案内文 |
| I-2 | セッション失効後の再サインイン導線が AppBar のアイコンのみ | 401 時に「再サインイン」導線。復帰時に静かに再認証 |
| I-3 | Android の戻るで即終了／記録シートの入力が無警告で消える | `PopScope` でタブ 0 へ戻す。シートは変更ありなら破棄確認 |
| I-4 | 基準地点編集で過去記録の距離・スコアが黙って再計算される | N 件再計算の確認ダイアログ |
| I-5 | 大フォントで記録カードのヘッダー行がオーバーフロー | 日付を `Flexible`＋ゼロ埋め、アイコン 2 個を `PopupMenuButton` に |
| I-6 | 未実装「近くの共有」タブと「メール認証は今後追加予定」が露出（Minimum Functionality リスク） | テスト期間中は非表示 |
| I-7 | 地図に OpenStreetMap の帰属表示なし（ODbL）。UA が識別性に欠ける | `RichAttributionWidget` 追加、`userAgentPackageName: net.riumu.reachtrail` |
| I-8 | サインアウトが無確認で削除ボタンの隣 | 確認ダイアログ＋削除はオーバーフローメニューへ |
| I-9 | 必須入力「制限時間」が保存後どこにも表示されない | 記録カードにタグ表示 |

## 軽微（各 30 分以内）

0 件表示の二重化、エラー色を `colorScheme.error` に、「基準値」→「基準地点」、手入力店舗 ID に `_newLocalId()`、価格入力の数字制限、`_mapController.move` のガード、`Place.fromJson` の座標欠損ガード、サインインのキャンセルをエラー扱いしない、`Yahoo`/`Mock Search` ラベルを debug 限定、未来日の訪問記録を禁止、README の存在しない UI 記述の修正、バックアップ挙動とサポート文言の整合。

## Play レビュー観点で問題なしと確認した項目

権限は INTERNET のみ、平文通信なし、アプリ内・Web 双方にアカウント削除導線、API キー非同梱、任意の Google アカウントでサインイン可。

## テスト期間中に観察して判断する項目

- 記録件数と Records タブの重さ（`ListView.builder` 化の要否）
- OSM タイルのレート制限・403 の有無
- Yahoo プロキシの 429 頻度（デバウンス／キャッシュの要否）
- 手入力登録と候補選択の比率、エレベータ乗車回数の入力率（スコアへの反映か削除か）
- 基準地点の変更頻度（複数基準地点の要否）
- タブレット・折りたたみのテスター有無（縦向き固定の見直し）
